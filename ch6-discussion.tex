\chapter{Discussion and conclusions}\label{chap:discussion_and_conclusions} % (fold)

% 1.性能和可靠性方面的技术限制插入损耗和信号劣化:光信号交换会引入功率损耗(例如6 dB 或更多),
% 削弱远距离传输，并且需要放大器，这会增加复杂性和发热量，从而抵消光通信系统(OCS)的效率优势.
% 可扩展性和稳定性问题:大端口OCS(例如,端口数超过1000个)面临精确对准的挑战(公差小于1毫弧度), 72x72, 144x144, not really for power of 2
% 通道间串扰以及对热/振动漂移的敏感性,导致性能不稳定.这些问题在超大规模系统中比在小规模系统中更难解决.

% 以太网的优势:电交换机避免了这些光通信的缺陷,提供可靠,低损耗的运行以及成熟的纠错机制.
% 谷歌在 Apollo 计划中通过优化波长(1310 nm 的 O 波段)和涂层解决了损耗问题,但此类调整需要定制化的工程设计

% 2.重配置速度慢, 不适合突发流量OCS 采用电路circuit交换模型,建立或更改连接需要物理机制,例如倾斜 MEMS 微镜或重新定向液晶，耗时 10-100 毫秒(某些设计甚至需要几秒).
% 这比以太网纳秒级的数据包交换慢几个数量级.数据中心流量通常是“突发性”且不可预测的,既包含短的“老鼠”流(例如Web 请求),也包含长的“大象”流(例如备份数据).
% OCS擅长为“大象”流提供专用、持久的连接,但会将容量浪费在未充分利用的电路上以处理短的“老鼠”流,并且无法在不中断链路的情况下处理快速变化,
% 从而导致丢包或停机。
% 以太网的优势:它提供细粒度的动态路由,且没有重配置延迟,使其成为通用工作负载的理想选择。超大规模数据中心通过混合设置(AI集群使用 OCS,其他所有设备使用以太网)来缓解这个问题,但改造并非易事.

% 3.集成复杂&生态系统不成熟OCS并非“即插即用”的替代方案,它们需要重新设计网络拓扑,用于流量调度的软件定义网络(SDN)控制器以及用于处理重连的协议(例如，“先建立后断开”冗余以避免中断).
% 这增加了拓扑优化和故障恢复的编排层数.供应商生态系统尚处于起步阶段——与以太网的即插即用环境相比,缺乏标准化接口——这使得多厂商互操作性存在风险.
% 以太网的优势:它经过数十年的实战检验,拥有丰富的软件工具,向后兼容性和全球支持.即使标准不断发展,诸如此类的采用障碍也会减缓 OCS的推广.

% 4.高昂的前期成本OCS 需要大量的初始资本支出(CAPEX),由于需要定制光模块,精密制造和集成,其成本通常是以太网交换机的3.5到6倍。虽然OCS有望带来长期的成本节约(例如,降低功耗和冷却成本,从而降低运营成本),
% 但投资回收期可能长达数年——这对于追求快速迭代的超大规模数据中心而言缺乏吸引力.扩展到超大规模端口数量(数千根光纤)会加剧成本,因为自由空间设计会受到小批量芯片制造等生产复杂性的影响.
% 以太网的优势:拥有来自 Arista 和Cisco 等供应商的成熟供应链, 从而能够以更低的成本和更快的速度进行部署。谷歌在Apollo 项目中通过设计与速率和波长无关,可在3,到 4 代硬件中重复使用的OCS来降低成本,
% 从而有效降低了约 30 percentage 的CAPEX,但这需要巨额的研发投入,鲜有其他方案能够匹敌.
